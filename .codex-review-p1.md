1. **MEDIUM — File-backed guests without an NBD disk now enter a live move that cannot advance.** `crates/engram-sandbox-firecracker/src/lib.rs:5375` and `crates/engram-host-agent/src/pooled_backend.rs:8264`. A File-mode guest on a host without the substrate, with a checkpoint chain and page server but a file-backed rootfs, previously returned no source view and selected snapshot rehome. It now passes presetup. The disk lookup still returns `None` (`pooled_backend.rs:8310`), but the coordinator requires a disk manifest and returns `ApiError::Internal("live export has no disk manifest")` (`crates/engram-coordinator/src/teleport.rs:436`). It never persists the export or selects snapshot mode; retry repeats the same failure. This is a supported configuration: NBD setup is optional (`crates/engram-host-agent/src/main.rs:678`), and the new test itself uses no NBD pool. **Smallest fix:** reject a missing live NBD disk with `InvalidSpec` during presetup, before publishing pending state, so the existing coordinator fallback selects snapshot rehome. Add a regression for that fallback; use an NBD-backed guest for successful live-move coverage.

2. **MEDIUM — Disabling an image makes its running File-mode guests fail capture after the pause.** `crates/engram-host-agent/src/pooled_backend.rs:8481`. Image reconciliation deliberately unlinks the per-image memfile while existing guests still map it (`crates/engram-host-agent/src/image_prefetch.rs:482-505`). Their new `memory_backing` field remains set, so presetup admits them. Linux reports the mapped pathname with ` (deleted)`, which `dirty_map::parse_maps_line` explicitly rejects (`crates/engram-host-agent/src/dirty_map.rs:82-86`). Capture therefore finds no VMAs and returns `Snapshot` after pausing. The coordinator rolls back instead of selecting snapshot rehome (`crates/engram-coordinator/src/teleport.rs:483-493`); each subsequent live attempt fails again. Re-enabling the image creates a new inode and does not repair the old mapping. **Smallest fix:** allow selection of the retained, deleted memfile mapping, with unambiguous mapping identity, or retain memfiles until their last live mapping is gone. Add an image-disable-then-capture regression. A presetup-only file-existence check is insufficient because disable can race capture.

3. **MEDIUM — The new CI test uses stock Firecracker for a fork-only capture API.** `crates/engram-host-agent/tests/postcopy_source_fresh_create.rs:184-191`. The fixture leaves `cfg.firecracker_bin` at `"firecracker"`. CI installs stock v1.16.0 at that name and stages the fork separately in `ENGRAM_FC_FORK_BIN` (`.github/actions/fc-setup/action.yml:100-139`). The test calls `migration_capture_postcopy`, which calls `snapshot_vmstate_only_package`; this sends `vmstate_only: true`, explicitly documented as rejected by stock Firecracker (`crates/engram-sandbox-firecracker/src/lib.rs:7100-7103`, `src/client.rs:308-323`). Thus the newly added CI target fails at capture before testing the VMA scan. **Smallest fix:** select the staged fork in the fixture and make the CI lane require that artifact. Keep any local missing-fork skip explicit.
